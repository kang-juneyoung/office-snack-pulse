# 인계 문서 — 스낵펄스 (개발부문 전달용)

## 검증 결과 요약 (데모 데이터 기준)
- 조사 14개 중 견적 요청 2건 → 견적 전환 약 14% (기준 10%) → **계속**
- 가장 많이 빠지는 단계: 랜딩 방문 → 총무 가입 (약 11%) → 다음 실험은 랜딩 문구 변경·가입 단계 축소
- 응답이 0인 조사(링크를 공유하지 않은 경우)가 14개 중 3개(약 21%) → 조사 생성 직후 "단톡방에 올릴 문구" 제공 실험 후보

## 데이터 구조
| 테이블 | 내용 | 개인정보 |
|---|---|---|
| users | 총무·내부 담당 계정 (role: manager/staff) | 이메일, 이름, 비밀번호 해시 |
| surveys | 조사 (owner_id, 인원, 공유 토큰) | 없음 |
| responses | 직원 응답 (간식 배열, 예산, 주기, 한마디, 브라우저 해시) | 없음 (이름·연락처 미수집) |
| quote_requests | 견적 요청 (연락처, 요청 사항) | 연락처 — staff만 조회 |
| events | 행동 이벤트 9종 | 익명 식별값만 |

## 인가 규칙 (lib/services.ts)
- `getOwnedSurvey`: 조사 소유자 또는 staff만
- `requestQuote`: 소유자만 (staff 대리 불가), 조사당 1회
- `funnelCounts`·`recentQuotes`·`eventCounts`·`overallPreferences`: staff만
- 화면은 이 함수만 호출하므로, 화면을 새로 붙여도 규칙이 유지됨

## 사용 수준으로 만들 때 바꿀 것
1. 테이블 생성 SQL > drizzle-kit 마이그레이션
2. 총무 가입 > 회사 이메일 인증 또는 기존 위펀 고객 계정 SSO 연동
3. 견적 요청 > 영업 CRM·슬랙 알림 연동
4. 이벤트 기록 > 사내 분석 도구(GA4·Amplitude 등)로 이관하고 이 테이블은 판단용 요약만 유지
5. 직원 중복 응답 방지 > 필요 시 사내 메신저 인증 연동
